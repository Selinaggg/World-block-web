# 首轮实物联调

空板、兼容的已烧录固件、USB 数据线。关闭旧硬件服务和 Arduino Serial Monitor。双击启动器，在设备设置确认底板数量、每行底板数、从左到右再从上到下的端口顺序。

自动发现仅在一个已知 USB 串口候选设备时连接。多个候选设备需明确选择；有设备序列号时保存它以便端口变化后找回。无序列号且端口名变化时需重新选择。

拔出设备时停止本次硬件子进程，插回后重新启动，沿用原数据库和恢复机制；不会自动重置板面。初始映射来自硬件配置：C0 Earth、C1 Fire、C2 Animal、C3 Human、C4 Water、C5 Support，必须按实物标签确认。

## 在 demo1-basic 检查

1. 空板进入：自动选择 Physical model，没有积木，状态正常。
2. 单块：检查数量、位置、类型，逐个测试六种编码；C5 仍占据一层。
3. 两层：底层稳定后再加顶层，检查类型和顺序。
4. 移除顶层：底层保留，上层消失。
5. 移动：取出等状态稳定后再放到另一位置，检查旧位置清空。
6. 方向：检查每块底板的边角、半层位置与排列。
7. 空板拔插 USB，再测试少量积木重连；离线期间先不要改动堆叠。
8. 输入通过后点击 Generate 3D 验证世界输出。图片生成单独测试。

recovering/attention 需人工核对，不自动清空、不跳过异常。当前文档的可靠范围为七层。串口打开或 health.ok 不等于所有位置可信。

## 排查

- 没有设备：检查数据线、供电、驱动和串口列表。
- 等待底板：检查固件兼容性、数量和串口占用。
- 端口冲突：关闭旧服务；启动器不会终止别人的进程。
- 仍是 Manual：保存设置后重新进入；原 npm run dev 不包含自动连接注入。
- 缺依赖：重新双击启动器；首次安装需要网络。
- 日志在 `runtime/hardware.log` 和 `runtime/demo*.log`。

Connection demo 是模拟；粒子梦境本轮仍是手动体验。软件检查不能代替实物联调。
