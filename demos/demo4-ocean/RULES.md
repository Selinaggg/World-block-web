# Demo 04 · Ocean｜海底世界规则

> 规则由 `worldblocks/src/rules.mjs` 决定；`worldblocks/src/world.js` 将规则结果画成三维生物与环境。没有 AI 图片生成步骤。

## 1. 体验与输入

空板已有海床、岩体、远景海草、光束、流动光纹和水中颗粒。这些是固定环境，不计入模块数量，也不代表已识别到硬件。

**放置 / 堆叠 / 移动 / 移除 → 完整输入状态 → 邻接关系 → 生物形态与行为 → 立即更新。**

每层都保留，C0–C5 在本 demo 中拥有下表的独立玩法含义。首页的底板数量与布局仍然生效；首页用于 Terrain/Basic/Town 的 Earth/Fire 等名称不会覆盖此处的生态角色。

## 2. 每种模块是什么

| 编码 | 英文名称 | 角色 | 单独出现 | 同类相连或堆叠 |
| --- | --- | --- | --- | --- |
| C0 | Reef | 礁体、孔洞、附着基底 | 起伏礁石、管状海绵、扇状附着体 | 邻接礁体融合为连续的大珊瑚礁；每层位置仍参与融合和生态规则 |
| C1 | Meadow | 海草、海藻植被 | 低矮海草丛 | 有同类邻居或位于更高堆叠层时变成长海藻；高度有上限 |
| C2 | Shoal | 游动生命 | 一小群开放水域鱼 | 增加局部鱼群数量；近邻环境决定体型、颜色与游动区域 |
| C3 | Symbiosis | 底栖与共生生命 | 海星 | 各层分别保留；礁区变小蟹，草区变螺类 |
| C4 | Luminance | 柔软、发光的生命 | 半透明水母，带发光边缘与触须 | 每层独立；低层连接礁体可变为附着型发光生命 |
| C5 | Current | 水流与养分的视觉影响 | 气泡与循环流动微粒 | 相连时出现流道连接；更多同类邻居扩大水层活动范围，最多按三个邻居增强 |

物种是风格化的生态表现，不是生物学仿真。可通过形态、颜色、活动位置和组合辨认不同生态角色。

## 3. 什么算链接

| 关系 | 是否链接 |
| --- | --- |
| 同一位置上下相差一层 | 是 |
| 同层、相邻一个完整格距 | 是 |
| X、Y、Z 三个方向都相差半格 | 是，对应错位网格的六边形面邻接 |
| 只在 X/Z 平面斜着接近，没有对应层高 | 否 |
| 鱼游到了另一个模块旁边 | 不改变模块链接 |

链接由已知位置与层高推算，不代表硬件识别了朝向、物体身份或真实接触接口。

## 4. 两种模块如何互相影响

| 条件 | 结果 | 去掉邻居之后 |
| --- | --- | --- |
| 礁体旁有海草 | 礁体长出分枝珊瑚，形成 Coral garden | 恢复普通礁体附着体 |
| 鱼群旁有礁体 | Reef fish：较丰富配色的礁区鱼 | 按剩余邻居重新选择 |
| 鱼群旁无礁体，但有海草 | Grass fish：细长的草区鱼 | 恢复开放水域鱼或水流鱼群 |
| 鱼群旁只有水流影响 | Ribbon shoal：沿水流方向拉长的循环路线 | 恢复普通绕行 |
| 底栖生命旁有礁体 | 小蟹、礁面活动 | 按剩余邻居变回草区螺类或海星 |
| 底栖生命旁无礁体，但有海草 | 草区螺类 | 恢复海星 |
| 发光生命处于 0 或 0.5 逻辑高度，且旁边有礁体 | Anemone：附着型发光触须群 | 变为漂浮水母 |
| 更高层的发光生命 | 保留水母形态，即使旁边有礁体 | 高度与邻接变化后重新判断 |
| 海草 / 鱼群 / 水母旁有水流 | 摇摆、路径方向或漂移范围改变 | 恢复缓慢的默认运动 |
| 相邻两个水流模块 | 两个位置之间出现可见流道 | 删除对应连接 |

## 5. 多模块涌现

| 名称 | 精确触发条件 | 画面反馈 |
| --- | --- | --- |
| Nursery habitat｜庇护区 | 同一个鱼群模块同时直接连接礁体与海草 | 礁区鱼体型更小、数量更丰富 |
| Night reef｜夜光礁 | 同一个礁体模块同时直接连接底栖生命与发光生命 | 礁上出现发光分枝与明亮端点 |
| Luminous garden｜发光花园 | 低层发光模块直接连接礁体 | 从漂浮生命转成附着型发光群 |
| Current corridor｜水流廊道 | 至少两个水流模块面相邻 | 沿水流块的位置连线生成流道；近邻生命同时响应 |

这里的“庇护区”不是繁殖模拟，“养分”不是数值资源系统。当前版本以程序化形态、数量与动画表现组合效果。

## 6. 同时满足多个条件怎么办

| 对象 | 形态优先级 | 可叠加的行为 |
| --- | --- | --- |
| 鱼群 | 礁区鱼 → 草区鱼 → 水流鱼群 → 普通鱼群 | 水流方向、庇护区数量与小体型可叠加 |
| 底栖生命 | 礁区小蟹 → 草区螺类 → 海星 | 维持各层自己的活动位置 |
| 发光生命 | 低层且邻礁时附着；否则漂浮 | 水流影响漂移 |
| 植被 | 同类邻接或较高层时为长海藻 | 水流影响摇摆 |

形态和配色使用模块位置的稳定种子。重复收到相同状态不会重建场景；相同摆法可复现相同的物种选择。鱼和水母仍会随时间运动。

## 7. 推荐摆法与检查

| 想验证 | 建议操作 |
| --- | --- |
| 物种会随链接变化 | C2 放在 L0-r0-c1；先独放，再在 L0-r0-c0 放 C0 |
| 庇护区 | 保持上述两块，在 L0-r1-c1 放 C1 |
| 每层保留 | 同一列放 C0 → C1 → C4；应同时存在礁体、植被与水母 |
| 附着 / 漂浮切换 | 低层 C4 旁放 C0，再把 C4 放到同列的第二层 |
| 连续水流 | 两个相邻列各放 C5，再在旁边放 C2 |
| 移除即时反应 | 移除礁体，观察鱼群形态与对应 Emerging 提示变化 |
| 无硬件预览 | Test view → Test board → 选择样例 → Load sample |

## 珊瑚礁融合（Living reef）

| 条件 / 操作 | 画面结果 |
| --- | --- |
| 两个 C0 礁体面相邻 | 融合为一张连续有机表面，连接处长出平滑的礁体组织 |
| 横向、竖向、半层面相邻 | 均支持融合；跨板边界同样按真实全局位置判断 |
| 多块连续连接 | 全部组成同一片礁体；保留各位置与邻近生态模块的影响 |
| 上方有同列礁体 | 下层不重复绘制被覆盖的顶部附着体，上层继续显示珊瑚细节 |
| 移除中间连接块 | 重新计算连通组；失去邻接的部分分裂成独立礁体 |
| 两块相隔或只在平面斜着靠近 | 不凭视觉接近建立融合 |
| C1、C4 等位于两礁之间 | 不充当礁体连接块，它们保留原来的功能 |

融合规则位于 `worldblocks/src/rules.mjs`；连续表面由 `worldblocks/src/reef-surface.mjs` 计算，`world.js` 负责附着体与渲染。

### 礁体的自然变化

- 模块位置决定固定随机种子，生成不同大小、偏移和分布的礁体凸起；相同输入可复现，不会每次收到硬件状态都重新随机。
- 已确认的面邻接仍由连续的礁体连接，不会因形状扰动断开；随机变化不影响编码、坐标和生态规则。
- 表面叠加多尺度几何起伏，并重新计算法线；材质添加矿物色差、细颗粒与凹孔质感。
- 顶部管状附着体使用不同数量、位置、粗细、高度和倾斜角度，避免整齐环状排列。
- `reef-surface.mjs` 控制轮廓与几何粗糙度，`reef-material.mjs` 控制表面材质，`world.js` 控制附着体分布。

## 固定位置与镜头

场景采用固定坐标原点，新增或移除其他板上的模块不会让已有模块整体平移。第一个模块出现时可以自动取景；已有模块后，普通增减、跨板编辑不会再自动重新居中或缩放。

**Reset view** 会主动调整镜头以容纳当前全部模块；**Load sample** 也会主动取景。若远处新增模块超出当前画面，可以缩小视图，或点击 Reset view。板排列变更属于显式改变输入坐标，因此会按新排列移动对应板上的模块。实现位于 `scenePlacement.mjs` 与 `Scene.jsx`。


## 一键随机测试

打开 **Test view** 直接进入独立模拟，不连接或写入硬件。选择一种 **Unit** 后，每点一次 **Add unit** 增加一个模块，实时更新场景。关闭面板仍保留模拟场景；顶部 **Return to hardware** 切回真实输入。

| 操作 / 规则 | 行为 |
| --- | --- |
| Unit 按钮 | 选择六类模块之一，选择本身不生成 |
| Add unit | 82% 优先落在板阵中央区域，18% 尝试外围；不会移动已有模块 |
| 聚集与堆叠 | 中央区域偏向已有模块附近；28% 尝试在已有位置堆叠，其余优先空位。无合适位置时回退至可用位置 |
| 容量 | 保留 8 个 2×4 底板及错层位置，每列最多 7 层；满板时停用添加 |
| Undo | 恢复上一次添加、手动编辑、清空、样例或布局修改前的状态，最多保留 100 步 |
| Precise placement & board layout | 展开后仍可指定板子、位置与堆叠，用于精确联调 |
| Block monitor | 默认收起，按需查看数字积木 |

随机位置由本 demo 的 `worldblocks/src/randomPlacement.mjs` 决定；生成规则和硬件协议保持不变。选择基于当前板阵布局，切换模块类型不会清空已有模块。
