# 网站开发与联调

先运行模拟服务并完成输入检查，再与硬件维护方连接实物。可以使用任意前端框架。
在 React 等框架中，将 connectWorldBlocks 放在生命周期中，并在销毁时调用 close；
避免热更新后重复订阅。玩法与视觉使用规范化 columns，自行定义每种类型的效果。

建议保留：连接状态、模拟模式标识、需关注的位置，以及“重新连接数据”按钮。
重新连接调用 client.reconnect()，它不重建硬件状态。数据接收与画面渲染分开，
必要时在 requestAnimationFrame 中只绘制最新状态。

## 同机联调

硬件方在 USB 连接电脑上运行连接服务，地址通常 http://127.0.0.1:8787。
在同一台电脑上启动你的网站，将 baseUrl 改为这个地址，source 改为 hardware。
无需网站去打开串口，也无需复制底层固件。网站开发电脑没有设备时继续用 8790 模拟服务。

localhost 是当前电脑，不是合作伙伴电脑。上线网站要连接现场 USB，需要另行设计本地桥接
或认证中继；HTTPS 页面还可能受混合内容和本地网络访问许可限制。当前包未实现公网中继。
本地服务没有认证，不能直接把整个 8787 服务暴露到公网。

## 最小联调清单

- 空板有完整空位置，不误显示模拟块。
- 放一块、叠第二块、拿掉顶层：类型、位置、顺序正确。
- 移到另一个位置：新旧位置同步，不凭显示层 key 推断个体身份。
- 不同底板排列：位置与实物对应，无重复偏移或镜像。
- 拔线/停止服务：网页标记断开；恢复后收到完整状态，不残留旧会话。
- 异常位置：保留提示，交由维护方核对；不要自动清空或重置。

重复 snapshot 是正常现象。触发声音、动画或生成时比较上一状态与当前状态，
同一状态不要反复触发。生成媒体建议由明确的交互触发，并保存当次输入副本。
费用、生成服务与凭据由各自应用配置在服务端，不放浏览器代码。

网页原型通过检查后，再确认实际玩法效果；硬件读取稳定与视觉表现可以分别迭代。
